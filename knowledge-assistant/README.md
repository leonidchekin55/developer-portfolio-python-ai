# Knowledge Assistant

## Облачное демо

Демо уже развёрнуто на Render: <https://portfolio-knowledge-demo.onrender.com>. Можно задать вопрос по встроенному примеру без входа. Чтобы загрузить собственные PDF, DOCX или TXT, создайте аккаунт: список документов, поиск и история изолируются по аккаунту. API доступен по адресу <https://portfolio-knowledge-demo.onrender.com/docs>; состояние сервиса — `/health/ready`.

Для сохранения аккаунтов, истории и метаданных между перезапусками Render бесплатный Blueprint использует внешний PostgreSQL. Задайте `DATABASE_URL` в настройках Render приватным URI проекта Supabase; используйте **Session pooler** (порт 5432), не сохраняйте URI в GitHub. В строке подключения пароль подставляется из пароля базы данных проекта. При переходе с SQLite существующие записи локальной базы автоматически не переносятся; встроенный демонстрационный пример создаётся приложением при запуске. Загруженные файлы сейчас остаются во временном хранилище Render и могут пропасть при перезапуске — сохраняются учётные записи/история/индексные данные в PostgreSQL, но надёжное хранение самих исходных файлов требует object storage.

В бесплатном облачном режиме поиск находит подходящие фрагменты документов текущего аккаунта и показывает источники. При настроенном `OPENROUTER_API_KEY` релевантные фрагменты и вопрос отправляются выбранной модели; целиком документ не передаётся. Без секрета используется поиск по тексту. Сессия хранится в подписанной HttpOnly cookie, пароли хешируются scrypt. Это портфолио-демо, не корпоративное хранилище: не загружайте конфиденциальные документы.

Чтобы включить AI-генерацию на Render, откройте сервис `portfolio-knowledge-demo` → **Environment** и добавьте `OPENROUTER_API_KEY` как secret, затем сохраните изменения и дождитесь перезапуска сервиса. Ключ создаётся в [OpenRouter](https://openrouter.ai/workspaces/default/keys). Выберите бесплатные модели; маршрутизатор `openrouter/free` выбирает доступную модель с нулевой стоимостью токенов. Никогда не помещайте ключ в исходный код, браузер или GitHub. Модель по умолчанию — `openrouter/free`; её можно изменить через `OPENROUTER_MODEL`.

## Полный RAG-режим и разработка

В репозитории также есть расширенная конфигурация с embeddings, Qdrant и Ollama для генерации ответов. Её можно развернуть на облачном сервере с подходящими ресурсами через корневой `render.yaml`. Локальный Docker Compose — только необязательный способ разработки и проверки; посетителю сайта он не нужен.

Стек облачного демо: FastAPI · Supabase PostgreSQL · поиск по фрагментам · опциональная генерация OpenRouter Free · React · Vite. Стек расширенной конфигурации: FastAPI · PostgreSQL · Qdrant · Redis · Celery · Ollama (`nomic-embed-text` + `llama3.2`) · React · Vite.

### Локальная разработка (не требуется для демо)

```bash
cp .env.example .env
docker compose up --build
```

Локально UI открывается по адресу <http://localhost:5173>, API docs: <http://localhost:8001/docs>. Загрузки доступны после регистрации. Ollama загружает модели при первом запуске; это относится только к локальной разработке.

## Поток данных

1. API проверяет расширение и размер файла (20 MB), извлекает текст через pypdf/python-docx.
2. Chunker формирует фрагменты с перекрытием; embedding-модель Ollama выдаёт векторы.
3. Qdrant хранит вектора и метаданные документа/страницы/индекса фрагмента.
4. Для вопроса API ищет top-k релевантных фрагментов, формирует grounded prompt и просит LLM отвечать только на основе контекста.
5. Для зарегистрированного аккаунта ответ, вопрос и источники сохраняются в его истории; клиент видит цитаты с именем файла и номером страницы. Анонимные запросы к примеру не сохраняются.

## Endpoints

- `POST /api/v1/auth/register`, `POST /api/v1/auth/login`, `POST /api/v1/auth/logout`
- `POST /api/v1/documents` multipart file upload (authenticated)
- `DELETE /api/v1/documents/{id}` delete an owned document
- `GET /api/v1/documents` список документов
- `POST /api/v1/chat` `{ "question": "..." }`
- `GET /api/v1/history?limit=20`
- `GET /health/live`, `/health/ready`

## Приватность и ограничения

Публичное демо поддерживает аккаунты и ограничивает документы, фрагменты, поиск и историю владельцем. Оно использует подписанные cookie-сессии без подтверждения email и восстановления пароля, поэтому не подходит для чувствительных данных. Перед production добавьте подтверждение аккаунта и сброс пароля, внешнее управление секретами, антивирусную проверку файлов и политику хранения. Также нужны лимиты на уровне reverse proxy, защита от prompt injection, контроль затрат/очередей, трассировка retrieval качества и управляемое удаление векторов.
