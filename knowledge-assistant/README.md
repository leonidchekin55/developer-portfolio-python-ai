# Knowledge Assistant

## Облачное демо

Демо уже развёрнуто на Render: <https://portfolio-knowledge-demo.onrender.com>. Откройте ссылку в браузере, загрузите PDF, DOCX или TXT и задайте вопрос — устанавливать или запускать программу на своём компьютере не нужно. API доступен по адресу <https://portfolio-knowledge-demo.onrender.com/docs>; состояние сервиса — `/health/ready`.

В бесплатном облачном режиме документы обрабатываются на сервере: поиск находит подходящие фрагменты текста и показывает их как источники. Если в Render задан секрет `GROQ_API_KEY`, к поиску добавляется генерация ответов Groq с цитатами; отправляются только найденные фрагменты и вопрос, целиком документы не передаются. Без секрета демо автоматически остаётся в режиме поиска по тексту. Это общее временное демо без аккаунтов и разделения документов по посетителям: загруженные документы и история вопросов могут быть доступны другим посетителям. Данные могут сброситься после перезапуска Render. Не загружайте сюда личные или конфиденциальные файлы.

Чтобы включить AI-генерацию на Render, откройте сервис `portfolio-knowledge-demo` → **Environment** и добавьте `GROQ_API_KEY` как secret, затем сохраните изменения и дождитесь перезапуска сервиса. Ключ выдаётся в [консоли Groq](https://console.groq.com/keys). Никогда не помещайте его в исходный код, браузер или GitHub. Модель по умолчанию — `openai/gpt-oss-20b`; её можно изменить через `GROQ_MODEL`.

## Полный RAG-режим и разработка

В репозитории также есть расширенная конфигурация с embeddings, Qdrant и Ollama для генерации ответов. Её можно развернуть на облачном сервере с подходящими ресурсами через корневой `render.yaml`. Локальный Docker Compose — только необязательный способ разработки и проверки; посетителю сайта он не нужен.

Стек облачного демо: FastAPI · SQLite · поиск по фрагментам · опциональная генерация Groq · React · Vite. Стек расширенной конфигурации: FastAPI · PostgreSQL · Qdrant · Redis · Celery · Ollama (`nomic-embed-text` + `llama3.2`) · React · Vite.

### Локальная разработка (не требуется для демо)

```bash
cp .env.example .env
docker compose up --build
```

Локально UI открывается по адресу <http://localhost:5173>, API docs: <http://localhost:8001/docs>. Ollama загружает модели при первом запуске; это относится только к локальной разработке.

## Поток данных

1. API проверяет расширение и размер файла (20 MB), извлекает текст через pypdf/python-docx.
2. Chunker формирует фрагменты с перекрытием; embedding-модель Ollama выдаёт векторы.
3. Qdrant хранит вектора и метаданные документа/страницы/индекса фрагмента.
4. Для вопроса API ищет top-k релевантных фрагментов, формирует grounded prompt и просит LLM отвечать только на основе контекста.
5. Ответ, вопрос и список источников сохраняются в истории PostgreSQL; клиент видит цитаты с именем файла и номером страницы.

## Endpoints

- `POST /api/v1/documents` multipart file upload
- `GET /api/v1/documents` список документов
- `POST /api/v1/chat` `{ "question": "..." }`
- `GET /api/v1/history?limit=20`
- `GET /health/live`, `/health/ready`

## Приватность и ограничения

Публичное облачное демо не предназначено для личных или конфиденциальных данных: в нём нет аккаунтов и изоляции документов между посетителями. Полная конфигурация RAG использует изолированную сеть серверных сервисов. Перед реальным использованием добавьте аутентификацию, изоляцию по пользователям и tenant, антивирусную проверку файлов и политику хранения. Для production нужны лимиты на уровне reverse proxy, строгая очистка пользовательского ввода, защита от prompt injection, контроль затрат/очередей, трассировка retrieval качества и управляемое удаление векторов.
