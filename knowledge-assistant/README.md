# Knowledge Assistant

## Облачное демо

Демо уже развёрнуто на Render: <https://portfolio-knowledge-demo.onrender.com>. Откройте ссылку в браузере и задайте вопрос по встроенному демонстрационному документу — устанавливать или запускать программу на своём компьютере не нужно. Публичная демоверсия работает только для чтения: загрузка файлов и сохранение вопросов отключены, а поиск, список документов и API истории ограничены демонстрационным примером. API доступен по адресу <https://portfolio-knowledge-demo.onrender.com/docs>; состояние сервиса — `/health/ready`.

В бесплатном облачном режиме поиск находит подходящие фрагменты демонстрационного текста и показывает их как источники. Если в Render задан секрет `OPENROUTER_API_KEY`, к поиску добавляется генерация ответов бесплатными моделями OpenRouter; найденные фрагменты и вопрос отправляются выбранной модели, целиком документы не передаются. Без секрета используется поиск по тексту. Публичный сервис не предназначен для пользовательских файлов и переписки. Загрузка разрешается только в собственной доверенной инсталляции при явной настройке `ALLOW_PUBLIC_UPLOADS=true`; такой режим не обеспечивает изоляцию пользователей и не подходит для публичного сервера.

Чтобы включить AI-генерацию на Render, откройте сервис `portfolio-knowledge-demo` → **Environment** и добавьте `OPENROUTER_API_KEY` как secret, затем сохраните изменения и дождитесь перезапуска сервиса. Ключ создаётся в [OpenRouter](https://openrouter.ai/workspaces/default/keys). Выберите бесплатные модели; маршрутизатор `openrouter/free` выбирает доступную модель с нулевой стоимостью токенов. Никогда не помещайте ключ в исходный код, браузер или GitHub. Модель по умолчанию — `openrouter/free`; её можно изменить через `OPENROUTER_MODEL`.

## Полный RAG-режим и разработка

В репозитории также есть расширенная конфигурация с embeddings, Qdrant и Ollama для генерации ответов. Её можно развернуть на облачном сервере с подходящими ресурсами через корневой `render.yaml`. Локальный Docker Compose — только необязательный способ разработки и проверки; посетителю сайта он не нужен.

Стек облачного демо: FastAPI · SQLite · поиск по фрагментам · опциональная генерация OpenRouter Free · React · Vite. Стек расширенной конфигурации: FastAPI · PostgreSQL · Qdrant · Redis · Celery · Ollama (`nomic-embed-text` + `llama3.2`) · React · Vite.

### Локальная разработка (не требуется для демо)

```bash
cp .env.example .env
docker compose up --build
```

Локально UI открывается по адресу <http://localhost:5173>, API docs: <http://localhost:8001/docs>. Чтобы проверить пользовательскую загрузку в собственной доверенной среде, установите `ALLOW_PUBLIC_UPLOADS=true` в `.env`. Не включайте этот флаг на общем публичном сервере без аутентификации и изоляции пользователей. Ollama загружает модели при первом запуске; это относится только к локальной разработке.

## Поток данных

1. API проверяет расширение и размер файла (20 MB), извлекает текст через pypdf/python-docx.
2. Chunker формирует фрагменты с перекрытием; embedding-модель Ollama выдаёт векторы.
3. Qdrant хранит вектора и метаданные документа/страницы/индекса фрагмента.
4. Для вопроса API ищет top-k релевантных фрагментов, формирует grounded prompt и просит LLM отвечать только на основе контекста.
5. В приватной конфигурации ответ, вопрос и источники сохраняются в истории; клиент видит цитаты с именем файла и номером страницы. Публичное демо работает только для чтения и ничего не сохраняет.

## Endpoints

- `POST /api/v1/documents` multipart file upload
- `GET /api/v1/documents` список документов
- `POST /api/v1/chat` `{ "question": "..." }`
- `GET /api/v1/history?limit=20`
- `GET /health/live`, `/health/ready`

## Приватность и ограничения

Публичное облачное демо использует встроенный документ: загрузка, общий список пользовательских файлов и сохранение истории отключены. Флаг `ALLOW_PUBLIC_UPLOADS=true` разрешает общие загрузки только в доверенном частном развёртывании; он не добавляет аккаунты или изоляцию по пользователям. Перед реальным публичным использованием добавьте аутентификацию, tenant-scoping для документов, фрагментов и истории, антивирусную проверку файлов и политику хранения. Для production нужны лимиты на уровне reverse proxy, строгая очистка пользовательского ввода, защита от prompt injection, контроль затрат/очередей, трассировка retrieval качества и управляемое удаление векторов.
